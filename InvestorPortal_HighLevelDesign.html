Investor Portal — High-Level Design v2

Database: MelissaFieldstone75LLC  |  Updated after design review

1. Design Decisions (From Review)

  • Separate Password Table — Credentials stored in a dedicated InvestorCredentials table, not in Investors
  • Login Audit Log Table — All login activity tracked in a dedicated InvestorLoginLogs table
  • Admin Role — Admin users can manage all investors; investors can only see their own data
  • No Self-Registration — Only admins can create investor accounts
  • Password Reset via Email — Token-based email reset flow
  • Containerized with Docker — Runs locally or can be deployed to cloud
  • Ports — Frontend on 4200, Backend on 8080

7. Password Reset Flow

1
Investor clicks "Forgot Password" and enters their email address
2
Backend generates a secure random token, stores it in InvestorCredentials.reset_token with a 1-hour expiry
3
Backend sends an email with a reset link: http://localhost:4200/reset-password?token=<token>
4
Investor clicks the link, enters a new password on the Angular reset page
5
Backend validates the token (exists + not expired), hashes the new password, clears the reset token
6
Investor is redirected to the login page
